# LAN Call 已知缺陷与限制（阶段一 v0.2.0，协议 v2）

## v1.2 安全修订（2026-10-22 外部评审）
1. **配对码离线穷举（已修复）**：v1 的 saltA/saltB/proofB 明文传输，
   10⁶ 码空间可被离线穷举。v2 改用 X25519 ECDH + SAS 双方屏幕比对，
   被动抓包无法离线求解；主动 MITM 会导致 SAS 不一致被用户发现，
   即使用户误确认，`pair-confirm` MAC 验证也会失败。v1 已废弃。
2. **enc 层重放/反射（已修复）**：v2 会话密钥经 HKDF 双向派生（kAB/kBA），
   每帧 AAD 绑定方向+序号，接收方严格校验，违例断开并告警。
   单元测试覆盖：重放/反射/序号跳跃/篡改（`test/unit.test.js`）。
3. **暴露面收敛（已加固）**：maxPayload 256KB、未认证连接上限 16、
   pair-request 按 IP 限流（5/分钟）、pair-confirm 失败 3 次冷却 60 秒、
   握手总超时 20 秒。

## 功能缺口（按阶段计划，本轮不实现）
1. 无局域网自动发现——阶段二（mDNS）实现，接口已预留（`src/discovery/index.js`）。
2. 无摄像头/麦克风选择——阶段三；当前默认设备。
3. 无断线自动重连——阶段三；当前断线仅提示。
4. 单实例只支持一路通话；来电占线时自动回 `busy`。
5. 无通话历史、通讯录（已配对设备列表除外）。

## 已知问题
1. **safeStorage 不可用时密钥只存内存**：极少数系统（无系统密钥环）上，
   配对密钥重启后丢失，需重新配对；UI 有黄色警告条。永不明文落盘（设计如此）。
2. **配对码为 6 位数字**：防暴力猜解依赖 120 秒超时 + proof 双向验证；
   阶段三可升级为 SPAKE2（`core/` 内替换，不改协议外层）。
3. **ICE 只用 host 候选**：要求双方在同一子网（或三层可达）；跨 VLAN/复杂路由
   未验证。阶段三可评估本机 TURN 兜底。
4. **Windows 防火墙**：首次监听需用户在系统弹窗中手动放行（不自动改规则）；
   若用户拒绝，连接超时提示为"对方可能未运行软件或被防火墙拦截"。
5. **单应用实例锁**：同一 Windows 用户下重复启动会聚焦已运行实例（符合桌面习惯）。

## 安全说明
- 媒体：WebRTC DTLS-SRTP（标准加密）。
- 信令：配对/认证完成后全程 AES-256-GCM；配对前仅传输 hello 与配对握手
  （不含任何 SDP/媒体信息）。
- 配对码显示在发起方屏幕，需面对面/电话告知对方；不知道码的第三方
  无法通过 proof 验证（已用单测覆盖错码与重放场景）。
- 渲染进程无 Node 权限（`sandbox:true` + `contextIsolation`），密钥不出主进程。
- 无账号、无遥测、无自动更新、无外部网络请求。
